## External release gates still NOT VERIFIED

1. **Authorization — satisfied:** the user explicitly requested Team 39 deployment and a website open to anyone with its link.
2. **Team/platform input:** actual FCSE team, repository root/branch/read access, CPU/RAM/disk quota and reviewer ingress policy. Prepared public ingress is not confirmed course permission.
3. **Target runtime:** build/start pinned Docker images; verify extensions, Linux DB/upload permissions, readiness, HTTPS cookies, subdirectory behavior and health/load at approved limits. Windows local execution is narrower evidence.
4. **Platform validation:** run actual RepoRun Validate and resolve findings. Static checks are not a substitute.
5. **Authorized live checks:** verify endpoint/database health, assets, authentication/authorization, bookings, simulated payments and uploads. A successful deployment operation alone proves none of these.
6. **Persistent redeploy:** create marker records/uploaded image, perform a normal redeploy and verify persistence/no duplicate seeding. Local repeat-migration row counts are not the same check.
7. **Recovery:** execute an isolated backup/restore rehearsal. Instructions exist; restoration has not been demonstrated.
8. **Content/accessibility review:** obtain current business confirmation/authorization, native-language review and screen-reader/manual review where formal assurance is needed.

No course submission, external evaluator result, official business approval, real payment, outbound email delivery or live deployment is claimed.
